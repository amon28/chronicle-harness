Claude Code (your subscription)

💻Claude Code in LinuxYour own Claude Code on this phone: install, sign in, start, usage›

Runs the Claude Code program you install in this app's 🐧 Linux, and its models appear in the model picker under “Claude Code (your subscription)” – pick one in any chat. It uses your own Claude plan. You sign in inside Claude Code itself, in the terminal – Chronicle has no sign-in for it and never reads, stores or backs up that sign-in. Installs @anthropic-ai/claude-code and its ACP adapter @agentclientprotocol/claude-agent-acp with npm (Node 22 or newer). Start runs the adapter behind acp-bridge on 127.0.0.1 only, with a new secret each time that stays in the app's memory. Claude Code's own files (~/.claude/.credentials.json, ~/.claude.json) are hidden from Files › Linux, assistants in other chats are asked before touching them, and backups leave them out. It needs a lot of memory and space (about 400 MB) and runs slower than on a PC.

…

  1. Install Node, Claude Code and its adapter in Linux.
  2. Sign in – yourself, in Claude Code: open the 🐧 terminal, type claude and follow its sign-in (it shows a link to open in your browser and a code to paste back).
  3. Start it in a folder in Linux, then chat.

            GitHubNot connected – git and gh in the Linux shell›
            
Lets the Linux shell (git clone / pull / push, gh) and the chat's Git history reach your repos. Being signed in on github.com in the assistant's browser is not enough: git needs a token, and this gets one.

            

            

              
Enter this code on GitHub, approve, then come back:

              

              
Waiting for you to approve…

            

            

              
              
              
            

            

              
            

            

              Paste a token instead
              
A fine-grained token (GitHub › Settings › Developer settings › Fine-grained tokens) limited to the repos you choose, with "Contents: read and write" and an expiry date. For an organisation repo choose the organisation as Resource owner (the organisation may have to approve the token). Only that repo is reachable, and it stops working on its date.

              

            

            
            

            

              SSH key (last resort)
              
An SSH key on your GitHub account reaches every repo you can push to and never expires – GitHub cannot narrow it. Use it only when a GitHub App or a fine-grained token is not possible (an organisation that will not approve them), and delete it on GitHub when you are done.

              
What the app does to keep it narrow: the key is made on this phone and kept in the app's secure store (never in backups); it is put into the shell only while it is switched on, and taken out when the time runs out; git uses it only for the repos listed here (this decides when git picks the key – on GitHub the key still reaches every repo you can push to); GitHub's server is checked against its published key; and each push asks you first. What it cannot prevent: a program running in the shell while the key is on could copy it – keep the time short.

              

              

                
                
                
                
              

              

                
                
                
                
                
              

            

            

              Use a GitHub App (recommended – needed for most organisation repos)
              
A GitHub App reaches only the repos you install it on, and its sign-in runs out after 8 hours and renews itself. Organisations that refuse OAuth Apps usually allow it. Once:

              
    
                
  1. GitHub › Settings › Developer settings › GitHub Apps › New GitHub App. Any name and homepage URL; untick Webhook; tick Enable Device Flow.
    2. 
                
  2. Repository permissions: Contents: Read and write (and Pull requests / Issues if you want those). Account permissions: Email addresses: Read. Nothing else.
    3. 
                
  3. Create it, then Install App › your organisation (or account) › Only select repositories › pick the repos. If you are not an owner, GitHub sends the owner a request to approve.
    4. 
                
  4. Copy the app's Client ID here and tap Sign in with GitHub. The ID is not a secret.
    5. 
              

              
An OAuth App's Client ID works here too, but it reaches all your repos and organisations can refuse it.

              
            

            
The sign-in can do what it was given, and any command the assistant runs in the shell can use it – so give it only the repos needed. The assistant is told never to make SSH keys or other credentials itself, and the shell asks you first if it tries. Outputs show [GitHub token] instead of the token.
